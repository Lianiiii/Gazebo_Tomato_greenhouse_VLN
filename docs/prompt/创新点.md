## 1. 现象回顾（与代码对应）

### 问题一：转弯过激，贴着 metal 拐，易单轮碰撞后绕轮打转
- 典型位姿：`x≈-0.095, y≈4.278, yaw≈-1.32`，前方 `metal_*` 需要左拐。
- 现象：明明有更大 clearance 的左拐空间，策略仍选择“贴障碍再拐”；右轮蹭到 metal 后，左轮继续驱动 → 绕右轮旋转卡住 → 导航失败。

### 问题二：起步不看两侧与脚下
- 相机视角“看起来可通行”，但脚下/近处 metal 会卡脚；随后转弯触发与问题一相同的物理失败模式。

这两类问题在农业大棚尤其突出：**细长金属支撑/轨道/底框** 高度低、横向间隙窄，与 NavDP 原训练/评测偏室内家具、开阔 clutter 的假设不同。

## 2. NavDP 算法端：与问题直接相关的机制

核心链路：

```
RGB-D → process_image / process_depth
     → RGB memory_queue（8 帧）+ 当前 depth
     → RGBD Backbone + Goal Encoder
     → DDPM 采样 16 条轨迹
     → Critic 打分 → 取 top-k 作为执行轨迹
     → 客户端 MPC 跟踪 → /cmd_vel
```

关键文件：
- `policy_agent.py`：预处理、memory、选轨迹后处理
- `policy_network.py`：扩散去噪 + critic 选轨
- `policy_backbone.py`：RGB/Depth token 融合
- `navdp_server.py`：HTTP 推理入口

### 2.1 深度预处理把“近处障碍”抹掉（强相关问题二）

`policy_agent.py` → `process_depth()`：

- `depth > 5.0` → 置 0
- `depth < 0.1` → 置 0

含义：
1. **0.1m 以内的近场深度被清空**。相机高度约 0.70m、前方近地 metal/轨道若落在近距离或画面底部，容易变成“无效深度”。
2. 无效深度在 backbone 里被当成 0 通道输入，**不等于“有障碍”**，更像“无信息”。模型容易把近处低矮障碍当成可通行。
3. 深度**只有当前帧**进入网络；`memory_queue` 只存 RGB，**没有深度时序记忆**。起步阶段 memory 还在 pad，时序上下文更弱，侧向/脚下风险更难累积出来。

→ 对应问题二的算法根因：**近场深度截断 + 无 depth memory + 相机俯视盲区**，共同造成“视觉可通行、脚下不可通行”。

### 2.2 轨迹表示是“相机系点轨迹”，不是“有轮距的机器人足迹”

扩散输出是 `predict_size=24` 的增量动作，再：

```python
all_trajectory = cumsum(naction / 4.0)
```

得到相机坐标系下的折线航点。随后：
- Critic 只对这条**点轨迹**打分；
- 客户端把相机系轨迹变到世界系，用 MPC 跟踪。

缺失项：
- **没有 robot footprint / wheel_base / 轮迹碰撞检查**；
- TomatoBot 轮距约 `0.32m`，底座约 `0.32×0.28`，转弯时外轮/内轮扫过的面积远大于“中心点轨迹”；
- 贴障碍 5–10cm 的中心轨迹，对点机器人可能“安全”，对差速车会**单侧轮先撞**。

→ 对应问题一的算法根因：**安全判据是点质量/学习到的隐式避障，没有显式 clearance 与轮迹约束**，农业窄通道里会系统性偏激进。

### 2.3 Critic 选轨：只按隐式价值排序，无几何安全重排

`predict_pointgoal_action()` 流程：
1. 采样 `sample_num=16` 条轨迹；
2. `predict_critic(naction, rgbd_embed)` 打分；
3. `(-critic_values).argsort` 取 top-2 作为 positive / 执行轨迹。

关键细节 `predict_critic()`：
- goal token 被 `cond_critic_mask` **屏蔽**（前 4 个条件位为 `-inf`）；
- critic 主要看“轨迹 + RGBD 是否像可通行”，**不显式看目标几何，也不显式看最小障碍距离**；
- 没有二次几何过滤：如 min clearance、曲率、轮迹占用、侧向距离等。

因此：
- 若训练分布里“贴边绕行”仍能成功（室内开阔、障碍厚实、摩擦友好），critic 会给贴边轨迹高分；
- 大棚金属细杆/轨道：**贴边成功域极窄**，同样高分轨迹在真实物理下失败。

另外，短轨迹处理：

```python
all_trajectory[trajectory_length < 0.5] *= [[0,0,1]]
```

只把过短轨迹改成纯旋转，**不惩罚“擦边大弯”**。nogoal 里曾有“短轨迹扣分”逻辑也被注释掉，说明作者也遇到过选轨偏好问题，但 pointgoal 仍无 clearance 相关惩罚。

→ 对应问题一：**多模态采样里其实可能存在更保守轨迹，但选轨准则不偏好 clearance**。

### 2.4 感知几何与农业场景不匹配（相机高度 / FOV / 障碍形态）

TomatoBot：
- `camera_height ≈ 0.70m`，水平朝前；
- 底座离地低、轮半径 `0.06m`；
- 大棚障碍多为**低矮细长金属**，落在图像下方/两侧边缘，甚至相机近处盲区。

NavDP 的 RGBD backbone：
- DepthAnything 风格 encoder，对“大块家具/墙”友好；
- 对细杆、低矮横梁、地面金属边的深度噪声更敏感；
- resize 到 224 + pad，**底部近地细节进一步被压缩**。

→ 问题二不仅是预处理阈值，也是 **传感器安装 + 特征分辨率对“脚下可通行性”表达不足**。

### 2.5 部署链路放大算法激进性（客户端 / MPC / 差速动力学）

即使算法端给出擦边轨迹，部署侧还会放大风险：

1. **MPC 纯跟踪、无障碍约束**（`mpc_controller.py`）：代价只有轨迹误差 + 控制平滑，`v∈[0,v_max], |w|≤w_max`，**不会因为靠近障碍而减速/外扩**。
2. **跟踪参考是相机系轨迹**，控制却作用在差速底盘；转弯时车体旋转中心与相机外参耦合，实际轮迹比规划中心线更靠外。
3. **单轮碰撞后的不可恢复**：差速模型在一侧卡住时仍发非零 `v/w`，表现为绕卡住轮旋转——这是问题一失败的最终形态，属于**规划激进 + 无卡滞检测/恢复**的组合。

结论：算法端负责“选了擦边轨迹”，部署端负责“忠实执行擦边轨迹且无安全阀”。创新点可以做在**算法端、后处理选轨、或客户端安全层**（不必改官方 server 权重也可做论文）。

## 3. 根因归纳（一句话版）

| 问题 | 主要根因（按重要性） |
|------|----------------------|
| 转弯贴障、卡轮 | ① 无 footprint/clearance 的点轨迹选优；② critic 不显式偏好安全边距；③ MPC 无避障约束；④ 差速单侧碰撞无恢复 |
| 起步踩/蹭脚下 metal | ① `depth<0.1` 近场清空；② 相机高、俯视盲区；③ 无 depth 时序/脚下占用表征；④ 农业低矮细障碍与训练域 gap |

**统一本质**：NavDP 把“避障”学成了视觉隐式偏好，而农业大棚需要的是**对低矮结构与轮迹宽度敏感的、带显式安全边距的通行性决策**。

## 4. 可落地方案（由易到难，不强制改官方权重）

### A. 客户端安全层（不改 server，最快验证）
1. **轨迹 clearance 重打分**：把 NavDP 返回的 `all_trajectory + all_values` 取回（server 已返回），用当前 depth 反投影做局部点云/代价地图，按“最小轮迹距离 / 车体膨胀半径”重排，拒绝擦边 top-1。
2. **近场脚下占用检查**：对图像下方 ROI + 近距离深度做 traversability；不通过则禁止前进，先原地旋转或后退。
3. **贴障减速 + 卡滞检测**：横向障碍距离小时降 `v_max`；里程计推进停滞但轮速非零 → 停车/小幅反向脱困。
4. **起步阶段强制扫描**：memory 未满前降低线速度、增大角速度探索，避免“视觉走廊假象”。

### B. 算法推理侧后处理 / 轻量改推理（可做对比实验）
1. Critic 分数 + **几何安全分数** 的加权融合：`score = α·critic + β·clearance + γ·smoothness`。
2. 提高 `sample_num`，在候选集里做安全过滤（保守轨存在但没被选中的假设可验证）。
3. 调整深度近场策略：`<0.1` 不要直接清零，可标为“未知高代价”或保留 raw 给安全层。

### C. 模型/训练向（论文主干，工作量大）
1. **Footprint-aware / wheel-trace critic**：训练或蒸馏一个对轮距敏感的价值函数。
2. **脚下可通行性辅助头**：预测 near-field occupancy / BEV traversability，与扩散策略联合。
3. **农业域数据与特权信息**：在大棚仿真里用 GT 占用/接触力做 privileged critic（延续 NavDP sim-to-real 思路，但换成农业几何先验）。
4. **多相机或俯视/倾斜相机**，补近地 FOV。

## 5. 面向毕业论文的创新点候选（建议选题结构）

下面按“可写成一章/一篇小论文”的粒度列。**推荐主线：C1 或 C2**；A/B 作为工程基线与消融。

### 创新点 C1（最推荐）：面向窄通道差速车的 **Safe Trajectory Re-ranking for NavDP**
- **问题定义**：端到端扩散导航在农业窄障场景系统性选择低 clearance 轨迹。
- **方法**：保留 NavDP 多模态采样；引入 **机器人足迹膨胀 + RGB-D 局部代价** 的安全重排序/拒绝采样；可选耦合速度缩放。
- **创新表述**：不是重训大模型，而是提出 **“生成式导航策略 + 农业场景几何安全选择器”** 的系统方法；强调与 embodiment（轮距）耦合。
- **实验**：成功率、碰撞率、最小 clearance、卡滞次数；对比 raw NavDP top-1 / critic-only / 你的 re-rank。
- **优点**：不碰官方 checkpoint 也能做；工作量可控；故事完整（问题来自真实迁移）。

### 创新点 C2（推荐）：**近场脚下可通行性感知** 增强的农业导航
- **问题定义**：高位相机 + 近场深度截断导致起步/近障“假可通行”。
- **方法**：Near-field Traversability Module（图像下方 ROI + 深度补全/分类）；与 NavDP 轨迹生成串联：不可通行则切换旋转探索或安全停。
- **创新表述**：**补齐 end-to-end 导航在近地结构上的感知盲区**，针对温室金属低矮障碍提出专用通行性表征。
- **实验**：人为放置脚下/侧向金属条；起步碰撞率、首次有效避障距离等。

### 创新点 C3：农业场景下的 **Clearance-aware Critic / 风险敏感选轨**
- 在 C1 基础上把安全项学成化：用仿真特权距离场监督一个 lightweight risk critic，推理时与原 critic 融合。
- 更“算法创新”，但需要训练与数据管线，适合作为硕士论文核心章节。

### 创新点 C4：**卡滞可恢复的差速导航闭环**
- 检测单侧碰撞/绕轮旋转（odom 与 cmd 不一致、IMU 角速度异常等），触发恢复策略，并反馈给规划层提高保守性。
- 偏系统与控制，可作第三章工程贡献，不宜单独当唯一创新。

### 创新点 C5：温室导航 **评测基准 / 失败模式分析**
- 把 metal 贴边转弯、脚下卡阻、窄垄通行整理成可复现 episode set + 指标（min clearance、wheel contact、stuck-spin）。
- 适合支撑上述方法，也可单独写成“农业仿真导航评测”小节。

## 6. 建议的论文叙事（可直接用作开题逻辑）

1. **背景**：温室巡检需要 mapless 导航；NavDP 等扩散策略在通用场景表现好。
2. **迁移失败**：在番茄大棚出现贴障急转与近地卡阻两类系统性失败。
3. **归因**（有代码证据）：点轨迹隐式避障、近场深度失效、无 footprint、跟踪层无安全约束、域差距。
4. **方法**：提出“NavDP 多模态轨迹生成 + 农业几何安全选择/近场通行性约束（+可选风险 critic）”。
5. **验证**：大棚仿真对比与消融；指标不止成功率，还包括 clearance 与 stuck-spin。
6. **贡献**：
   - 揭示通用 E2E 导航向农业窄障迁移的关键失效机制；
   - 提出 embodiment-aware 的安全选轨/近场通行性方法；
   - 建立面向温室金属障碍的评测与实验结论。

## 8. 我的建议优先级（给恋）

1. **先做 C1 的最小原型（客户端 re-rank）**：用 server 已返回的 `all_trajectory/all_values` + depth 做 clearance 重排，尽快定量证明“不是没有好轨迹，而是没选出来”。这会直接支撑论文 claim。
2. **并行补 C2 近场 ROI 检查**：专门打问题二。
3. **把 C5 失败用例固化成评测集**，后面所有方法都在同一套 episode 上比。
4. 若时间充裕，再把安全分数升级为 **C3 可学习 risk critic**，抬升“算法创新”比重。

## 9. 本次结论摘要

- 问题一的根因不只是“模型笨”，而是 **点轨迹 + 隐式 critic 选优在窄金属障上偏激进**，再被 **无安全约束的 MPC/差速执行** 放大。
- 问题二的根因是 **近场深度被预处理抹除 + 相机盲区 + 无脚下通行性表征**。
- 最适合硕士论文、且与你现状匹配的创新点：**在不推翻 NavDP 的前提下，做农业场景 / 差速 embodiment 感知的安全轨迹选择与近场可通行性约束**，并用大棚仿真把失败模式评测化。
